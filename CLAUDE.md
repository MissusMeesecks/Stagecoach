# Stagecoach — notes for coding agents

Lumiverse Spindle extension. Read `docs/stagecoach-brief.md` first; it is the design record.

Hard rules from the brief:
- Never write to character cards (no `characters.update`, no `extensions` blob).
- The interceptor in `src/backend.ts` is pure: read caches, splice, return. No LLM calls, storage writes, or state mutation there.
- Only the current stage's card may reach the prompt. Later stages never appear, in any form, until their tier says so.
- Ask before adding permissions beyond `characters`, `chats`, `interceptor`, `generation`.

Toolchain: `bun install`, `bun run verify` (tsc + bun test + build). Commit `dist/` after building; the host runs the checked-in bundle.
Platform types: `lumiverse-spindle-types` in node_modules (docs.lumiverse.chat may be unreachable from sandboxes).
Findings from live tests: names resolve via the macro engine; trailing/mid-history system messages were ignored by the roleplay model, appending to the user turn steers at once (so append is the default).
Per-stage transition styles (route.transitions, keyed by stage hash) shape only the arrival wording; default is 'elapse' (narrated time skip), and the legacy 'auto' value maps to it. Only scene and mood reach the model; presupposes is a read-only context line, doneWhen is parked.
Append mode wraps the directive as `(OOC: …)` (parentheses on purpose: `[OOC: …]` is the host's regen-feedback marker). Arrival directives end with a keep-tense-and-voice note; the in-stage tail (guidance + tense note) is `DEFAULT_IN_STAGE_INSTRUCTIONS`, user-replaceable via `settings.inStageInstructions` (global, edited under the card preview; null = default).
Decided: one note per stage, on the first reply after Advance; stage 1 never gets a note. Back is a silent undo: the stage it lands on keeps its old entry, so no note; only a stage arrived at by Advance gets the note. The note is its own control: one button next to the stage controls reads the panel's estimate and offers the opposite, "Skip this note" (`route.skipNote`, honoured by the interceptor, cleared by any pointer move) or "Send scene note" (`replayStage`, refreshes the current stage's entry and anchor in place). Advance then Skip = move forward silently. The stage controls are disabled while the chat toggle is off.
Known gap: the panel's "next reply: …" line and the Skip/Send button label are an ESTIMATE from the message count (`turnsInStage`, count minus entry over two) because the frontend cannot see message roles. In group chats, where members reply with no user turn between, it can lag the interceptor by a reply or two (e.g. still saying "scene-change note" after a member's reply consumed it). The interceptor is authoritative: it counts real landed replies after the anchor. If this gets a PR, the fix is to give the panel roles (host message list with `is_user`, or counting bubbles after the anchor id via `ctx.dom.listMessageElements`), not to change the interceptor. The optional in-stage reminder (route.timing.reminderEvery) is off by default and has no UI; both a repeated note and a note on every reply looped the scene.
On the Lumiverse build this was developed against (Sept 2026), the frontend had no ctx.messages.get; the opening greeting is read from the mounted first-message bubble in the DOM instead. The frontend sends every reading it can get (API content, bubble for index 0, topmost mounted bubble) and `src/core/opening.ts` matches them: exact first, then chunk-sampled containment, best score wins; on no-match the panel shows what it read. Raw generate calls need an explicit connection id and model.
Distill must send the connection's model explicitly (top-level and in parameters) or OpenRouter answers "No models provided".
Group chats (Sept 2026): a group chat's `chat.metadata` holds `group: true`, `character_ids` (members), `activeGreetingIndex` (which greeting opened the chat) and `talkativeness_overrides`; `{{group}}` does not resolve. `src/core/group.ts` reads these. Greetings are pooled from every member (backend `chatGreetings`, cached per chat, cleared with the character cache and on CHAT_CHANGED); `GreetingInfo.characterId/Name` say whose card each is and the panel badges it. `{{char}}` on a card is the card's owner, resolved from the character record when the owner is not the speaker. The card's optional `with` field names the scene partner (blank = {{user}}; other members offered as quick picks) and renders as "This scene is between {char} and {partner}." after the scene. Append mode falls back to a system message at the route depth whenever the latest history message is not the user's (a member spoke without a fresh user turn, or a solo Continue); the Depth control shows in append mode as "Fallback depth". The note goes to whoever speaks next after Advance. `activeGreetingIndex` is also the fallback for opening-greeting detection when the text cannot be matched or read. The `with` field is group-only: hidden in solo chats and ignored by the renderer there (`RenderOptions.group`), so a card shared with a group cannot steer a solo chat. In group chats the partner line always appears ({{user}} when `with` is blank), and naming another character in `with` makes {{user}} in that card's scene/mood mean them; names come from the character record, not the macro engine, since the host's card-macro mode may point {{char}} at whoever is active. Distill uses the pooled greetings, so any member's card distills.
"First reply after Advance" is counted from replies, not turns: `repliesSince` in tiers.ts counts assistant history messages after the anchor message (`route.anchors[stageIndex]`, the latest message id at Advance), falling back to `sourceIndexInChat >= enteredAt`. Index-delta/2 fired the note up to three times when members replied back to back. Only landed replies count: an empty assistant history row (placeholder for the reply being written) and the context's excludeMessageId are ignored, and the append fallback looks at the latest history turn with text. The interceptor logs one line per generation (replies, rule, tail) so "nothing fired" reports can be read off the host log. A dry run before you send has no fresh user turn, so it shows the note as the system fallback; the real generation after you send appends it.
Phase status: v1 built, tested and extended. Auto-advance, strength and the judge were dropped by decision.
