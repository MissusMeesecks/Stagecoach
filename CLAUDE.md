# Stagecoach — notes for coding agents

Lumiverse Spindle extension. Read `docs/stagecoach-brief.md` first; it is the design record.

Hard rules from the brief:
- Never write to character cards (no `characters.update`, no `extensions` blob).
- The interceptor in `src/backend.ts` is pure: read caches, splice, return. No LLM calls, storage writes, or state mutation there.
- Only the current stage's card may reach the prompt. Later stages never appear, in any form, until their tier says so.
- Ask before adding permissions beyond `characters`, `chats`, `interceptor`, `generation`.

Toolchain: `bun install`, `bun run verify` (tsc + bun test + build). Commit `dist/` after building; the host runs the checked-in bundle.
Platform types: `lumiverse-spindle-types` in node_modules (docs.lumiverse.chat may be unreachable from sandboxes).
Findings from live tests: names resolve via the macro engine; trailing/mid-history system messages were ignored by the roleplay model, appending to the user turn steers at once (so append is the default).
Per-stage transition styles (route.transitions, keyed by stage hash) shape only the arrival wording; default is 'elapse' (narrated time skip), and the legacy 'auto' value maps to it. Only scene and mood reach the model; presupposes is a read-only context line, doneWhen is parked.
Append mode wraps the directive as `(OOC: …)` (parentheses on purpose: `[OOC: …]` is the host's regen-feedback marker). Arrival (scene-change) directives, the only notes sent by default, end with the closing line: `settings.closingLine` (global, edited under the card preview with "Edit the closing line"; null = TENSE_NOTE, "Keep the existing narrative tense and voice."). The in-stage tail (guidance + tense note) is `DEFAULT_IN_STAGE_INSTRUCTIONS`, replaceable via `settings.inStageInstructions`; it only reaches the model on chats an older version left with in-stage reminders on, and its editor ("Edit the reminder wording") only shows there.
Decided: one note per stage, on the first reply after Advance; stage 1 never gets a note. Back is a silent undo: the stage it lands on keeps its old entry, so no note; only a stage arrived at by Advance gets the note. The note is its own control: one button next to the stage controls reads the panel's estimate and offers the opposite, "Skip this note" (`route.skipNote`, honoured by the interceptor, cleared by any pointer move) or "Send scene note" (`replayStage`, refreshes the current stage's entry and anchor in place). Advance then Skip = move forward silently. The stage controls are disabled while the chat toggle is off.
Known gap: the panel's "next reply: …" line and the Skip/Send button label are an ESTIMATE from the message count (`turnsInStage`, count minus entry over two) because the frontend cannot see message roles. In group chats, where members reply with no user turn between, it can lag the interceptor by a reply or two (e.g. still saying "scene-change note" after a member's reply consumed it). The interceptor is authoritative: it counts real landed replies after the anchor. If this gets a PR, the fix is to give the panel roles (host message list with `is_user`, or counting bubbles after the anchor id via `ctx.dom.listMessageElements`), not to change the interceptor. The optional in-stage reminder (route.timing.reminderEvery) is off by default and has no UI; both a repeated note and a note on every reply looped the scene.
On the Lumiverse build this was developed against (Sept 2026), the frontend had no ctx.messages.get; the opening greeting is read from the mounted first-message bubble in the DOM instead. The frontend sends every reading it can get (API content, bubble for index 0, topmost mounted bubble) and `src/core/opening.ts` matches them: exact first, then chunk-sampled containment, best score wins; on no-match the panel shows what it read. Raw generate calls need an explicit connection id and model.
Distill must send the connection's model explicitly (top-level and in parameters) or OpenRouter answers "No models provided".
Settings section (bottom of the panel, `renderSettings`): the Distill model and the Higher token limit switch are global (`settings.distillConnectionId`, `settings.highTokenLimit`); Injection mode and depth stay per chat on the route. The card editor shows which model Distill will use but has no picker. The switch selects `HIGH_TOKEN_LIMITS` over `STANDARD_TOKEN_LIMITS` (shared/types.ts, every budget doubled): directive cap, card target and cap, closing-line (and in-stage instructions) length and Distill's per-field word limit move together. The interceptor passes `tokenCap` from the cached settings. `core/settings.ts` normalises stored settings and panel patches; stored instructions are never re-capped on load, so switching the limit off loses nothing.
Group chats (Sept 2026): a group chat's `chat.metadata` holds `group: true`, `character_ids` (members), `activeGreetingIndex` (which greeting opened the chat) and `talkativeness_overrides`; `{{group}}` does not resolve. `src/core/group.ts` reads these. Greetings are pooled from every member (backend `chatGreetings`, cached per chat, cleared with the character cache and on CHAT_CHANGED); `GreetingInfo.characterId/Name` say whose card each is and the panel badges it. `{{char}}` on a card is the card's owner, resolved from the character record when the owner is not the speaker. The card's optional `with` field names the scene partner (blank = {{user}}; other members offered as quick picks) and renders as "This scene is between {char} and {partner}." after the scene. Append mode falls back to a system message at the route depth whenever the latest history message is not the user's (a member spoke without a fresh user turn, or a solo Continue); the Depth control shows in append mode as "Fallback depth". The note goes to whoever speaks next after Advance. `activeGreetingIndex` is also the fallback for opening-greeting detection when the text cannot be matched or read. The `with` field is group-only: hidden in solo chats and ignored by the renderer there (`RenderOptions.group`), so a card shared with a group cannot steer a solo chat. In group chats the partner line always appears ({{user}} when `with` is blank), and naming another character in `with` makes {{user}} in that card's scene/mood mean them; names come from the character record, not the macro engine, since the host's card-macro mode may point {{char}} at whoever is active. Distill uses the pooled greetings, so any member's card distills.
"First reply after Advance" is counted from replies, not turns: `repliesSince` in tiers.ts counts assistant history messages after the anchor message (`route.anchors[stageIndex]`, the latest message id at Advance), falling back to `sourceIndexInChat >= enteredAt`. Index-delta/2 fired the note up to three times when members replied back to back. Only landed replies count: an empty assistant history row (placeholder for the reply being written) and the context's excludeMessageId are ignored, and the append fallback looks at the latest history turn with text. The interceptor logs one line per generation (replies, rule, tail) so "nothing fired" reports can be read off the host log. A dry run before you send has no fresh user turn, so it shows the note as the system fallback; the real generation after you send appends it.
Per-user caches: one worker can serve several users, so every backend cache lives in a per-user bucket (`cachesFor(userId)`). Cards are content-addressed, so two users with the same public card share greeting hashes; a shared cache handed one user's cards and settings to the other. `actingUser` resolves a missing user id (events may omit it) to the only user seen since the worker started: right on a single-user install, but on an operator install it can be a user who has not been seen yet, so anything acting on that fallback must stay harmless if the guess is wrong. Once several users have been seen there is no fallback: CHAT_FORKED without an id is skipped, and a frontend message without one is dropped, since a reply to nobody broadcasts. The interceptor resolves its (always present) id without recording it, so it stays side-effect free. Cache fills re-check after the storage read, so a save that landed meanwhile wins. `src/backend.test.ts` boots a fresh copy of the real backend per test against a fake two-user host; every test stands alone, and the races are staged by holding a storage read open (`holdNextRead`).
Theme variables: highlights use the user's theme accent, as Lumiverse's own primary buttons do (checked against its theme engine, frontend/src/theme/engine.ts upstream): fill `--lumiverse-primary`, label `--lumiverse-primary-contrast` (the engine computes it from the accent, so custom themes stay legible), hover `--lumiverse-primary-hover`; the current stage gets the accent border plus `--lumiverse-primary-010`; accent-coloured text ("card ready", "customized") uses `--lumiverse-primary-text` on dark and the accent on light (`[data-theme-mode="light"]` on <html>). Fallbacks are Lumiverse's defaults. `--lumiverse-accent`/`-accent-fg` are not Lumiverse variables (the old CSS used them, so highlighted buttons rendered transparent). The `.sc-primary` hover rule must restate the label colour, or the generic button hover recolours it. Status colours: danger (running light, errors), success (done), warning (failed).
Permissions: the startup prompt asks for all four together. The host's prompt is all or nothing, so if it is refused, Stagecoach offers once to continue without Distill (the three core permissions only). The startup prompt comes back only while a core permission (characters, chats, interceptor) is missing, so someone who has the core three but not generation is not nagged; `ensureGeneration` (Distill, List connections) asks for it when needed.
Card editor: it closes when the chat changes (`editingChatId`; the home screen in between does not count, so A -> home -> A keeps the draft), with a notice if the draft had unsaved changes, and likewise when its greeting leaves the chat's characters (text edited, or member removed from a group; a state that failed to load is not counted). Notices are cleared on a chat change and on the home screen. Distill status is per greeting hash (`distillStatus`), so several cards can distill at once, and a late result or failure lands only on the open editor for that hash. Status is set before the permission check (no double sends). Each press carries a `runId` that the backend echoes on `distill_result`/`distill_error`; a reply is applied only while its run is still the running one, so a reply from a run the panel gave up on, or replaced with a retry, never overwrites what was typed since. The no-reply timer starts when the call goes out (not while the permission prompt is open); after 130 s (the backend aborts at 120 s) the run turns to failed. A failure's reason shows under the Distill row, and one persistent live region (`announcer`, kept across renders) reads out status changes only, and says when a run was not sent; the visible light has no role. Under the preview: a warning block when the note is trimmed (`.sc-warning`, warning colour, bold lead, saying what was cut from the renderer's `fieldsIntact`/`tailIntact`; the box gets a solid warning border, the count a "trimmed" flag per note, and the route list a "⚠ Note trimmed" line under the stage, not a head-row badge, which crushed the title on narrow panels; a "close to the cap" footnote when names could tip it over, allowing about 3 tokens per `{{char}}`/`{{user}}` in the note and at least 6), the card's token count and the scene-change note against its cap (the line can break before each flag and before the count, so a narrow panel wraps it), then how the note goes in; then [Distill + light] and [closing-line toggle + badge] in one row, each pair wrapping as a unit. Route and greeting rows (`itemHead`): the title keeps about 9em (full text as its tooltip), and the badges and buttons are one cluster that wraps under the title as a unit, right-aligned, when the row is too narrow; narrower still, the buttons wrap under the badges, together. A button is never left on a line of its own (the old single flex row crushed the stage-1 title to nothing at the default drawer width and pushed ✕ off the edge). Just above Save, the stage's Way in (`wayInRow`, the same picker as the route list's; it saves at once via set_transition) for stage 2 onwards on this chat's route, or a hint saying why there is none.
Editor preview (decided: it shows what is sent): `core/preview.ts` holds `noteOptions` (Way in from the route, token cap, closing line, in-stage instructions, group), which the interceptor renders with too, and `previewNote`, which places the card in this chat: 'sent' (stage 2+: the scene-change note goes out once, on the first reply after the story moves forward onto it), 'stage-one' and 'off-route' (not sent here; the box shows what it would read, dimmed), or 'empty' (no scene or mood: nothing). A legacy in-stage reminder (reminderEvery >= 1, no UI) is previewed as a second box. Names stay literal ({{char}}/{{user}}); the append wrapper or system placement follows the chat's injection mode. Parity tests in backend.test.ts (solo, and a group with a `with` partner at the higher cap) check the preview's text against what the interceptor appends. {{char}}/{{user}} in the closing line and the reminder wording are filled in like the card's fields, but as global texts: {{user}} stays the user even when a group card names another partner, and {{char}} is whoever replies (`RenderOptions.textNames`, the speaker's record name in a group), not the card's owner. The renderer reports `tailIntact` (closing line or instructions survived trimming) so the panel need not re-derive it. The panel's isGroup comes from the chat record (groupInfo), as the interceptor's does, even when a member fails to load. render() keeps the focused field (marked `data-focus-key`: card fields, the text editors, the depth box, the Way in pickers) focused across a rebuild: text fields with their caret when their text is unchanged (when it changed underneath, as with a Distill result, focus is dropped instead); the Way in pickers even when their value changed. While it runs, `rendering` is true, so the blur/change a removed field fires is not taken as the user leaving it. The text editors save on blur (a box rebuilt and refocused by render() fires no change), Done or Reset; the depth box keeps half-typed digits in `depthDraft` (cleared on a chat change). render() also keeps the scroll position of the panel and of every scrolling ancestor: removing the focused element mid-rebuild (a clicked button keeps focus) makes the browser lay out the half-emptied panel, which clamps the scroller towards the top (users saw a jump when opening or hiding the closing-line editor, and on Done). Because notices are drawn at the top, a new notice or state error is scrolled into view once (`revealNotice`): a notice is new by identity, so the same failure twice scrolls twice; a state error by its text; one going away never scrolls; and while a text field is being typed in it waits for the next render with no text field focused, since the next keystroke would scroll back to the caret. While a pointer is down in the panel, render() waits until it is released (or a value is picked in the panel, or a second passes, since a release inside a dropdown popup never reaches the page), so a rebuild cannot swallow a click.
Phase status: v1 built, tested and extended. Auto-advance, strength and the judge were dropped by decision.
